# 更新日志

## 0.3.0 — 比较审批与任务生命周期升级

从 0.2.6 升级的功能版本，包含六阶段改进。版本仍处于 0.x；本次工作流行为变化用 0.3.0 表达，不因代码行数增加直接宣布 1.0 稳定版。

### 主要变化

- 当前 Agent 先接收候选原文与版本、比较事实/变化/适用范围/依据，再提出可批准的变更；完全重复无需卡片，不能完成分析时保持未分析。
- 批次身份、完整内容摘要和目标版本绑定真实用户批准；跨进程写入协调、稳定身份与安全重放覆盖聊天、面板、编辑和删除。
- 卡片展示推荐依据及旧新片段，面板展示完整原文/差异；明确未审、暂缓、拒绝、重复和批准，修改内容须重新分析与确认。
- 有限期决定账本抑制相同拒绝/重复建议，待审提案复用；新依据/版本或用户主动重审可继续。
- 新增第五个 task 工具及临时任务账本；显式新目标/阶段/收尾、dirty、待审和恢复可查看。请求前即使零记忆工具调用也提供有限的当前正式正文。
- 长续接保留任务；历史待审引用核对真实批次；检索失败不误报恢复，整体自动上下文包含分隔符仍不超过 8,000 字符。

### 升级与使用变化

- 旧 propose(items) 调用只准备候选，不再直接返回保存卡；使用 prepare/page → propose(reviewToken, decisions) → 原样 asktool 或面板批准。
- 旧待审批次重新展示时升级并保留已写入身份；未分析项及重启遗失的分析/批准需重新比较和确认，旧卡片不能继续写入。
- 正式 Markdown 仍使用原项目目录，不自动全量迁移。降级前备份 .workflow；旧版本识别新待审批次/临时状态的完整行为未验证。
- Plan/Goal 显式 search/load/prepare/task status 及结果追踪零写入；扩展缺少 mode 字段，未知模式自动临时任务写入获得独立授权。正式记忆仍需人工批准。
- 自带受限 Node 写入不经宿主逐次文件权限审计。结束通知不能强制 Agent 再运行语义检查；正文提供不证明理解，声称使用是 Agent 声明。

## 0.2.1

修复三处现场报告的缺陷，其中第一处让 `map` 类型完全无法写入。

**`map` 无法创建（严重）**

- 症状：项目还没有地图时，`kind=map` 的确认卡片只给「不保存」；强行提交新建会被拒绝，磁盘上永远不会出现 `MAP.md`。
- 根因：`core/batch.js` 的 `optionsFor` 在没有 active `map` 时返回空选项数组，`askOptions` 随后把推荐项也一并滤掉。
- 修复：无地图时给「新建」（落盘 `MAP.md`），已存在时给「更新」；地图目标直接从语料取出，不再依赖检索命中——因此「地图已停用」与「提议文本与地图无共同词」这两种原本也会死路的情况一并修掉。
- 这是 0.1.0 引入的回归：原插件没有 `map` 类型，其 `optionsFor` 恒含「新建」。此前所有 `map` 用例都自带一个已存在的地图，这个分支零覆盖。现在补上「每种 kind × {无相似, 有相似} 至少有一条可保存选项」的不变量测试。

**卡片自定义输入框**

- 症状：输入任何与标签原文不同的文字都被判为不是卡片上的选项，且不回显可用选项——卡片缺选项时用户彻底无路可走。
- 修复：标签匹配改为归一化比较（NFKC / 大小写 / 空白折叠）并剥掉「推荐 · 」装饰，手打标签也能命中；匹配失败时列出卡片上可用的标签。不做语义猜测。

**状态回报与磁盘不一致**

- 症状：第一轮说已保存 4 条，第二轮（只作答最后一张卡）却说「没有保存任何条目」「5 条还没有你的决定」，而那 4 个文件已经在磁盘上。
- 根因：`commitBatch` 的 `pending` 只看本次的内存态 `savedAs`，没有用已经算好的 `batchRef` 反查结果；批次从磁盘重读会丢掉 `savedAs`。
- 修复：已落盘条目不再计入 `pending`，结果新增 `already` 字段单独回报（确认面板同步），只有「本次没写且此前也没落盘」才说「没有保存任何条目」。

- 测试总数 198 → 208（新增 `map` 创建、地图单例不变量、答案归一化、状态回报四组回归）。


## 0.2.0

新增**工作面板视图**「项目记忆」：跟当前项目绑定的常驻入口，卡片式浏览本项目的全部记忆。

**视图（`views/`）**

- 入口：工作面板头部菜单里的「项目记忆」，随当前项目过滤，切换项目自动重载、丢弃未完成的编辑。

**安全边界（相对 0.1.0 的唯一放宽）**

- Agent 扩展**仍然无法删除记忆条目**：它的 remove 被限制在存放已处理批次的 `.workflow/memory-inbox`。
- 视图渲染仓库内容时全部转义，且不据其生成任何链接或图片；`test/view-ui.test.js` 是这套转义规则的 XSS 回归测试。

## 0.1.0

首次发布。基于 `axc00.project-knowledge` v0.3.3 的重设计，思路不变、实现重写。

**记忆模型**

- 六种记忆类型：`lesson` / `rule` / `decision` / `procedure` / `map` / `preference`，统一存储形态，用 frontmatter 的 `kind` 区分。
- 两层注入：项目地图与 `pinned` 条目**常驻**（限流 8 条 / 1200 字符），其余按查询检索（strict 门槛，最多 5 条）。
- 注入块按 kind 打标签（`[lesson]` / `[howto]` / `[decision]` …），模型能分辨步骤与取舍。
- 存储路径改为 `.workflow/memory`（不兼容原插件的 `.workflow/knowhow`）。

**去掉的能力**

- 移除可选 Jev 去重：不再需要 `net.fetch`，插件**完全不联网**。去重改为纯本地启发式。
- 移除 `fs.delete`：插件进程永不删除文件。

**修复**

- 幂等性：条目写入 `batchRef`，重试时反查已落盘条目并采纳，不再依赖「把批次写回 inbox 成功」这一脆弱前提；写回失败不再被静默吞掉。
- 注入净化：把去尖括号 + 截断抽成单一函数，**所有**从仓库数据拼出的文本（卡片选项标签、asktool 问题、决策说明）统一调用；条目 `id` 增加格式白名单。
- 分词：停用词表移除 `file`/`code`/`function`/`class`/`error`/`type`/`interface` 等代码高频词（此前它们永不参与检索）；脚本覆盖扩展到假名/谚文；**单字中文查询不再返回空**。
- 词边界：ASCII 词改用词集合精确匹配，`know` 不再命中 `knowledge`。
- 排序确定性：用 code-unit 比较替代 `localeCompare`，重复 id 胜出与同分排序不再依赖宿主 ICU。
- 缺失判定：只用结构化 error code，权限类错误不再被当成「缺失」静默跳过。
- 日期：改用本地日期，不再因 UTC 跨零点差一天。
- 循环上限：id 分配与存在性探测都有上限，超出抛错。
- 读取预算：新增 16MB 总字节预算（原先最坏可达 512MB）。
- 性能：检索改为一次遍历建立命中矩阵，IDF 与打分从矩阵派生；条目预处理缓存在 `WeakMap` 而不是挂在共享对象上。
