## 1. 目标

1. 相似条目出现时，由当前 Agent 先读取并比较，给出有依据的处理建议，再由用户批准具体变更。
2. 让新任务、阶段转换、压缩恢复与收尾的记忆检查具有可查看的状态，减少漏查与重复提醒。
3. 修复提交校验、跨进程竞争、确认版本绑定和审批状态混淆等已发现问题。

保留项目内 Markdown、无需额外模型服务、人工确认正式记忆写入的原则。Agent 读取和比较仍消耗当前会话 token。

## 2. 执行与暂停规则

- 第 0 段已保存计划。用户已确认并实施第一段；每段交付后暂停，后续阶段分别等待用户确认。
- 每次只执行当前获准的一段；不得因本段完成而自动进入下一段。
- 每段开始时核对现有代码、用户改动和本段前置条件；按仓库约束完成必要设计检查。
- 每段结束时更新本文件的状态及执行记录，并向用户报告：
  1. 已完成内容和主要文件；
  2. 实际验证命令、结果及尚未验证事项；
  3. 阻塞或需要用户判断的事项；
  4. 下一段的范围和预期变化。
- 随后停止工具操作，等待用户决定继续、调整、补充验证或终止。
- 原有未跟踪文件 `.agents/`、`project-memory-architecture.html`、`skills-lock.json` 不纳入本计划改动。
- 不修改 `D:\Codes\PI-Desktop`。宿主增强需单独提出方案并取得授权。
- 不自动提交、推送或发布；每段结束可给出提交建议。最终打包、安装及外部分发按用户授权执行。
- 不把尚未执行的设计、测试或安装验证标记为完成。

## 3. 范围与能力边界

### 本计划包含

插件工具和扩展、纯逻辑模块、待确认面板、记忆管理视图、回归测试、必要的设计与使用文档。

### 本计划不包含

向量数据库、外部 embedding 服务、独立后台模型、全局记忆同步、全量历史迁移、正式条目 ID 体系重设计，以及宿主级 Agent 文件权限沙箱。

### 不能承诺的能力

现有宿主 `agent_end` / `turn_end` 是通知事件，不能要求 Agent 再运行一轮。因此插件可以记录、提示和检测遗漏，**插件单独升级无法保证最终回复前必做语义记忆检查**。

正式记忆的用户确认约束落实于插件自己的写入路径。普通 Bash/Edit 仍可能直接修改文件，插件权限不能约束整个 Agent；完整目录权限保护属于宿主议题。

## 5. 第一段：提交规则与确定性正确性

### 范围

- 重用同一套输入约束，在提交时检查批次内同 kind/title 重复项及多个 map。
- 校验 action 白名单、key/action/target 一致性、必要目标、目标种类和合法动作；从可信规则构造可执行操作，拒绝改写 inbox 放宽规则。
- 查明退役地图和非标准路径地图的处理方式；创建/更新不得静默覆盖历史或制造第二个有效地图。现有异常数据需明确报告，不做未经批准的迁移。
- 先检查可访问语料范围内的确定性正文重复，再限制用于展示的检索候选；相同标题不再单独作为弃用旧条目的依据。
- 本段仍使用现有工作流；不宣称已实现语义比较或审批版本绑定。

### 主要文件

`plugin/core/batch.js`、`entries.js`，必要的 `main.js` 接线及相关测试。

### 验收

- 未知 action、伪造 option、非法目标、批内重复和多个 map 均在正式文件写入前失败。
- 三条同名候选之外的确定性正文重复可被识别。
- 同名不同正文不自动推荐弃用。
- 退役/异位地图场景不会静默覆盖；失败有可理解的错误。
- 新增针对失败场景的回归测试，`node --test` 全部通过。

### 暂停点

汇报规则行为变化、地图处理策略及测试证据；下一段是跨进程与确认版本保护。

## 6. 第二段：跨进程互斥与确认版本保护

### 范围

- 统一正式记忆写入协调，覆盖面板提交、扩展提交、编辑、删除和关联更新。
- 以跨进程互斥保护重读、ID 分配、正式条目写入和批次状态更新；确定宿主 fs API 支持后选择实现，不能用进程内 Set 冒充跨进程锁。
- 定义锁超时、取消、进程异常恢复和所有者验证；不得仅因等待时间较长就抢走仍有效的锁。
- 卡片/面板批准绑定提案 revision/digest，目标绑定 baseHash；提交时重读，变化即 stale，必须重新比较和确认。
- 摘要或批准版本必须保存在可信侧或经过真实答案绑定；不能依赖可一起改写的 inbox JSON 自我校验。支持聊天、面板及必要的重启恢复路径。
- 引入稳定 itemId，重放依据批次与条目身份，兼容现有未处理批次的策略需明确说明。

### 验收

- 展示后改写提案或目标，不会沿用旧批准写入。
- 两个独立进程竞争同批次、同目标时不重复、不丢失更新。
- 模拟部分写入失败、进程退出、锁等待超时及重试，结果收敛。
- 普通编辑、删除与确认提交的并发行为一致。
- `node --test` 全部通过，新增真实子进程竞争测试。

### 暂停点

汇报可信批准绑定方式、锁策略、兼容行为及已测边界。如宿主 API 不足，先报告具体缺口并等待决策，不擅改宿主。

## 7. 第三段：候选准备与 Agent 比较协议

### 范围

- 新增候选准备接口，返回命中理由、候选 ID、版本及全文读取入口；读取范围和预算要明确。
- 当前 Agent 读取原文，提交处理建议、依据、相同点、变化点、适用条件、新正文和候选版本。
- 合法建议包括新建、补充更新、替代、不同条件共存、重复无需写入；无法完成比较时返回未分析状态。
- 插件验证准备快照、被读取版本及建议目标，生成绑定版本的确认提案；这些校验不能证明模型推理必然正确，用户仍批准结论。
- 完全重复默认不弹卡；语义重复允许不写入，但保留可查看的理由。
- 跨 kind 候选仅用于提醒；不自动以一种类型替换另一种类型。
- 导入使用同一协议；无活跃 Agent 时保留未分析，不启动隐藏后台模型。
- 适配 Plan/Goal 的只读 action 与 planSafeActions；不得在只读动作中写正式记忆，热度等旁路副作用按宿主要求处理。
- 工具名、旧 propose 的兼容入口、语言描述及预算在本段确定并记录。

### 验收

- 候选 → 全文读取 → 建议 → 确认的工具链可测试，准备和分析不写正式语料。
- 建议引用当前候选版本，目标变化会失效；旧调用不能绕过比较和批准保护。
- 预算截断、无命中和未完成比较均明确标识。
- Plan/Goal 只读工具注册与动作限制通过校验；无法实测的宿主行为单独注明。
- `node --test` 全部通过，工具声明和运行时描述保持一致。

### 暂停点

展示实际工具调用样例和生成卡片，用户判断分析信息是否足够、调用成本是否合理。

## 8. 第四段：审批界面与决定去重

### 范围

- 聊天卡片展示推荐结论、目标、理由及旧新关键片段；面板提供完整差异。
- 显式区分未审、暂缓、拒绝、重复、批准；未勾选项保持未审，不能自动当成拒绝。
- 提供采用建议、修改后重新确认、暂缓、不保存和合法替代动作；修改正文后旧批准失效。
- 以内容、目标版本和有限保留期去重拒绝建议；新证据、版本变化和用户主动请求允许重审。
- 管理视图展示 related/替代关系，并解释共存适用条件。
- 来源和适用范围采用必要的可选字段，不把所有经验变成复杂表单。

### 验收

- 卡片及面板足以判断变更，不只有“有相似请判断”。
- 未审不会随保存所选被拒绝，暂缓仍可继续处理。
- 重复事件不产生第二份卡；新证据不会被旧拒绝永久压制。
- 中英文案、转义、安全边界、编辑草稿及焦点行为有回归覆盖。
- `node --test` 全部通过，并对实际 DOM/浏览器做可行的交互验证；安装态验证需用户配合时明确列出。

### 暂停点

展示界面及交互结果，等待用户判断审批方式和信息密度，再进入任务检查。

## 9. 第五段：任务生命周期、恢复与诊断

### 范围

- 建立 taskId、目标摘要、阶段、已读条目版本、dirty 标记、检查结果和待审提案索引。
- 临时任务状态与正式记忆分离，限制大小和保留期，不保存完整对话或敏感工具输出。
- 显式 begin/checkpoint/finish；新任务按目标检索，阶段变更时按需提醒。
- 收尾记录有新知识、已有知识覆盖或无需保存；检查不等于弹卡，不强迫每个任务产出记忆。
- 压缩前保存已有续接状态，压缩后恢复短索引；不阻止必要压缩，不把草案当成已批准事实。
- 通知事件用于标记和记录，请求前接口用于补充有限上下文；按阶段版本更新，避免每请求加入变化时间戳破坏缓存。
- 展示检索/无命中/失败、全文读取、阶段检查和待审数，区分 surfaced、loaded 与声称的 used。
- 用户等待审批是合法暂停状态，按任务/阶段/变化去重，不循环催问。

### 验收

- 新任务、同会话第二任务、继续短消息、多阶段工具链、压缩恢复和收尾都有可查看状态。
- 无记忆、检索失败和未完成检查可区分；失败不阻塞正常工作。
- 草案不进入正式事实注入；缓存稳定与信息预算有测试。
- 重复事件不重复提议或无限提醒；明确展示插件不能强制最终语义检查的边界。
- `node --test` 全部通过；真实长任务验证与单元模拟分别报告。

### 暂停点

汇报真实触发覆盖和仍依赖 Agent 遵守的部分。若用户需要强收尾保证，另立宿主计划，不纳入下一段自动实现。
