# 项目记忆插件调研与改进方案

调研日期：2026-10-10。对象：ProjectMemory-Pi-Desktop，main `3583def` / 0.2.6；只读核对 PI-Desktop 宿主。此次没有修改插件或宿主，没有提交或发布。

分段实施与暂停规则见 [执行计划](../plans/2026-10-10-memory-workflow-improvement.md)。本文件是 0.2.6 基线的调查记录，后续实现状态以计划执行记录为准。

## 结论

需要改进。当前自动化止于“检索摘要+固定提示”，相似裁决止于“正文相等/标题相等的本地启发式”。推荐方向：本地候选发现 → 当前 Agent 读取与比较 → 提交带证据的建议 → 人批准具体变更 → 插件校验并写入。保留项目内 Markdown、无需额外模型服务、人工写入确认。

触发改进需要区分：插件可记录状态、在请求前检查并注入；现有宿主结束事件不能延续 Agent，因此插件单独升级不能保证最终回复前必做记忆检查。强保证需要独立的宿主结束前检查接口。本方案不授权修改宿主。

## 已确认根因

### 相似提示为何让人从头判断

- `plugin/core/batch.js:133-150 findSimilar`：仅同 kind，标题精确匹配优先，其后关键词检索，只留 3 条。候选发现没有语义判断。
- `batch.js:183-193 heuristicDecision`：正文相等推荐重复；标题相等推荐替换；其他推荐新建。标题相同不能证明旧知识已经失效。
- `plugin/main.js:65-86 propose`：直接生成待确认批次并返回 asktool，不返回供 Agent 比较的候选原文。
- `batch.js:271-285 askToolArgs`：新正文截断到 200 字；卡片没有旧正文、差异、适用条件或新证据。通常只有一个焦点候选可选，其他候选在面板才能选。
- 所以不只是文案问题：工作流中没有 Agent 先比较的环节。

### 为什么开头、长任务中和结尾容易不使用

- `plugin/extension.js:309-316` 仅注册 session_start / before_provider_request / before_agent_start / tool_result。session_start 只固定目录。
- `extension.js:35` 提示“进入新子系统或两次失败时搜索”，没有明确新任务前检查；`:45` 收尾仅固定提示，无执行状态或完成验证。
- `extension.js:196-211` 只用最新用户文本检索并按消息缓存。长工具链不会因进入新目录、得出新结论而更新任务目标；“继续”一类消息可能没有可召回概念。相同请求的缓存稳定是好事，问题是缺少独立的任务/阶段状态。
- `extension.js:169-174` 自动检索 strict，需强命中标题/关键词；无命中时通常没有可见状态，用户难区分未运行和运行无结果。
- 宿主 `packages/agent-runtime/src/runtime.ts:3688-3698` 在 Plan/Goal 仅展示声明 planSafeActions 的工具；插件未声明，因此这两种模式中不能调用 search/load/propose。
- 宿主 `extensions/event-capabilities.ts:39-69`：agent_end/turn_end/session_compact 只是通知；`extensions/runner.ts:56-70` 的 sendMessage/registerLifecycle 等未实现。不能照搬 Claude Stop hook。

## 建议实现

### 优先级 P0：提交正确性与确认绑定

1. 所有正式记忆写入走同一受保护提交协议；为插件进程和 Agent 扩展提供跨进程锁。锁范围覆盖批次读取、语料重读、分配 ID、写条目及更新关联；限定持锁时间，明确异常恢复，避免永久等待。
2. 待确认操作从可信规则重建：action 白名单、key/action/target 一致、目标种类和单例约束、批内同 kind/title 重复检查。不要信任 inbox 内任意 options。
3. 卡片展示内容绑定提案 revision/digest；收到答案时校验展示版本与当前批次一致。digest/版本需要保留在可信侧，不可仅与可一同改写的 JSON 自我比较。
4. 提案带旧条目 baseHash，提交重读并比较；变化则标 stale，重新比较、重新确认，不能静默覆盖。
5. 每个提案项有独立稳定 itemId，重放依据 batchId+itemId；避免只靠可修改的 kind/title 恢复。

### 优先级 P1：Agent 先比较，人批准结论

新增两阶段接口（工具名可另定）：

1. `prepare(items)`：只读候选发现，不生成正式确认卡。返回候选 ID、命中原因、摘要、当前版本、完整读取路径/分页接口。先全量检查确定性正文重复，再做关键词候选；跨 kind 相似作为只读警告，不自动互换类型。截断时明确“展示前 N 条，可能还有其他候选”。
2. 当前 Agent 读取相关候选原文，比较：同一事实吗？增加了什么？适用条件相同吗？旧结论真的失效吗？新证据是什么？不确定时明确缺什么信息。
3. `propose(reviewToken, decisions)`：接受操作、目标、理由、相同点、变化点、新正文、证据和候选版本。插件校验 prepare 快照及合法操作，再生成用户确认卡。
4. 卡片直接给推荐结论，例如“建议更新 X：新增 Windows 条件，保留 Linux 步骤”；提供旧/新关键片段及完整 diff 面板；选项为采用建议、修改后确认、暂缓、不保存，另可展开合法替代动作。
5. 确定性完全重复默认不弹卡，向 Agent 返回已有 ID；Agent 判断的语义重复可静默跳过永久写入，但留下简短可查看的理由。若用户明确要求审核，仍可展示。
6. `暂缓`、`未审`、`拒绝`、`重复`、`批准` 分开记录；未勾选不再自动代表拒绝。相同内容+目标版本未变的拒绝在有限期内去重，新证据或用户主动请求可重审。
7. 导入同样走此流程；没有活跃 Agent 时保留“未分析”，让人主动触发比较，不能把启发式推荐标成 Agent 已分析。

保留现有替代关系/历史文件；稳定 ID 和原地更新属于后续数据模型决策，不要求本轮同时迁移。

### 优先级 P2：可检查的任务生命周期

任务与会话分离，保留小型本地临时状态（不进入正式记忆，不注入为已批准事实）：taskId、目标摘要、阶段、已读条目版本、待审提案、记忆检查时间、dirty 标记。避免记录完整对话或敏感工具输出。

- **开始**：首次任务/显式 begin 形成状态，按目标+相关模块检索。读取后给一句采用哪些旧知识/没有适用项；允许无记忆。一个会话可以开启多个任务。
- **阶段**：Agent 显式 checkpoint；模块变更、连续失败等事件只标 dirty 并在下次请求前提示。通知事件不能自行完成语义整理。
- **压缩前**：保存已经形成的续接状态，不临时要求智能总结，不阻止必要压缩。
- **压缩后/恢复**：补充紧凑恢复索引与需重读版本；已批准事实和待审草案严格分开。
- **收尾**：Agent 显式 finish，记录有可复用知识/已被现有知识覆盖/确实没有三个结果。无值得保存项可以结束，不强迫凑卡。
- **去重**：按 taskId+phaseId+变化摘要去重；等待用户确认属于合法状态，不重复追问、不循环续跑。

插件侧可在 `before_provider_request` / `context` 注入当前检查状态和有限提示，在 tool_result 记录读取/准备/确认结果。缓存按稳定阶段版本更新，避免每个请求加入变化时间戳损害缓存。

可见诊断：最近自动检索、查询来源（目标/模块/用户消息）、命中/无命中/失败、最近读全文、阶段检查与待审数。先展示“已检索/已读”，不要把“已注入”统计成“Agent 已使用”。

### 优先级 P3：宿主可选增强，单独授权

新增有返回语义的结束前检查接口，可按需注入一次记忆检查任务并延续 Agent。区别回合结束与任务完成；设置续跑次数、去重、超时、取消和审批等待放行。不能拿现有 agent_end 通知返回值冒充实现。对受控写入还需宿主保障目录权限，普通 Bash/Edit 可绕过插件接口，插件权限本身不构成整个 Agent 的安全沙箱。

只读 Plan/Goal 兼容属于插件实施范围，按照宿主 ADR 0211：工具提供可验证的 action enum，声明只读 planSafeActions；prepare/search/load 可开放，正式提交仍受确认约束。现有 search/load 没有 action 字段，需要设计兼容调用，不可只添加元数据。

## 验收标准

- 有相似候选时，推荐能引用已读原文版本，并解释变化/条件/依据；不再只有“有相似请判断”。无法读完整信息时明确未完成比较。
- 同名不同条件不会被直接推荐弃用；第 4 条确定性正文重复不会被漏掉；无价值重复不弹卡。
- 任意正式写入都有真实批准及一致内容版本；批次/目标被改写后拒绝旧批准。跨进程冲突不丢更新，重试不重复。
- 未审/暂缓/拒绝互不混淆；重复事件或用户等待不制造第二份卡片。
- 多阶段任务和压缩恢复可看到检查状态与下一步；结束未检查能被检测，插件版明确只提示保证，宿主增强版验证有限续跑。
- search/load 在 Plan/Goal 可用且无正式记忆写入；未确认提案不进入已批准事实注入。
